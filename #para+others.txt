  Kernel depth: 3×3×3×3 = 81 positions. The MLP takes 6 rotation-invariant scalars at each of these 81 positions and

  Question 2 — Where spatial and temporal resolution come from

  Yes, they come from pixdim in the NIfTI header. The raw header field is:

  pixdim = [qfac,  pixdim[1], pixdim[2], pixdim[3], pixdim[4], ...]
             ↑         ↑          ↑          ↑          ↑
           sign    H voxel    W voxel    Z voxel      TR

  nibabel's get_zooms() strips pixdim[0] (qfac) and returns pixdim[1..4].

  Our mapping (because our volume is [H, W, Z, T]):
  sy = zooms[0] = pixdim[1]   # H axis voxel size
  sx = zooms[1] = pixdim[2]   # W axis voxel size
  sz = zooms[2] = pixdim[3]   # Z axis voxel size
  TR = zooms[3] = pixdim[4]   # time between volumes

  Time unit handling — xyzt_units stores the declared unit ('mm', 'sec', 'msec'). The problem: the prediction file
  stores TR=1500.0 but labels it 'sec' — clearly wrong (1500 seconds is 25 minutes). Our heuristic catches this:
  if time_unit == "msec" or (time_unit == "sec" and TR > 100):
      TR /= 1000.0   # treat as milliseconds → convert to seconds
  → 1500.0 ms ÷ 1000 = 1.5 s ✓

  tr_slice is the one thing that cannot be read from the header — it depends on the scanner's slice acquisition order,
  which is not stored in standard NIfTI. You set it manually as TR / num_slices.
